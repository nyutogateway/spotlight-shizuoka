# WordPress 化の仕様

静的サイトとして作ってあるものを WP に載せ替えるときの設計。
いまの `data/*.json` と `assets/css/style.css` のクラス設計を前提にしている。

---

## 1. いまの構造（移行元）

| | 数 | 中身 |
|---|---|---|
| 記事 | 20件（→25件） | `data/articles/{slug}.json` |
| 一覧 | 1件 | `data/entries.json`。記事の抜粋 + グループ分け |
| グループ | 4組（→5組） | 5件ずつ。1件目が大きいカード（`lead`） |

記事1件が持つ項目：

```
no  vol  slug  lead  title  company  person  position
site  profile  name_en  image  image_alt  logo  body
```

本文（`body`）のブロック種別と、20記事ぶんの実数：

| 種別 | 数 | 表示 |
|---|---|---|
| `h` | 80 | 章見出し（中央寄せ・上に罫） |
| `q` | 140 | 質問（Q のバッジ付き） |
| `a` | 140 | 回答（A のバッジ付き） |
| `p` | 67 | 地の文 |
| `img` | 135 | 写真 |

## 2. 投稿タイプと固定ページ

### 固定ページ

| ページ | テンプレート | 備考 |
|---|---|---|
| TOP | `front-page.php` | Hero + VOICE 一覧 |
| CONTACT | `page-contact.php` | フォームは 8 章 |
| プライバシーポリシー | `page-privacy.php` | 本文は content で編集可 |

### 投稿タイプ

記事は**カスタム投稿タイプ `story`** を1つ作る。

- `has_archive: false`（一覧は TOP が持つ）
- `rewrite: ['slug' => 'story']` → `/story/{slug}/`
- `supports: ['title', 'editor', 'thumbnail', 'page-attributes']`

`page-attributes` は 3 章の並び順プラグインが `menu_order` を使うため。

---

## 3. 並び順とグループ（プラグイン管理・1〜25）

並び順プラグイン（Intuitive Custom Post Order など）で **1〜25 を管理**する。

**重要**：グループと通し番号は並び順から**計算で出す**。ACF の項目にはしない。

```php
$order = $post->menu_order;              // 1〜25
$group = (int) ceil( $order / 5 );       // 1〜5
$vol   = ( ( $order - 1 ) % 5 ) + 1;     // 組の中の 1〜5
$lead  = ( $vol === 1 );                 // 組の先頭＝大きいカード
$no    = sprintf( '%02d', $order );      // 01〜25
```

これで、いまの `no` / `vol` / `lead` / グループ所属の**4項目が不要**になる。
並べ替えるだけでグループも先頭カードも自動で追従するので、入れ替えのたびに
番号を振り直す作業が消える。

グループの色（現在 `#0A4E86` ほか4色）は記事ではなくグループの属性なので、
**テーマの設定（ACF オプションページ）に5色**まとめて置く。

## 4. ACF の設計

「共通なところはできる限りまとめる」方針で、**フィールドグループを3つ**に絞る。

### 4-1. `story_profile`（投稿タイプ `story`）

記事の顔まわり。一覧カードと記事ヘッダーの両方がこれを見る。

| フィールド名 | 型 | 対応 | 備考 |
|---|---|---|---|
| `person` | テキスト | 人物名 | 例「宮本 功」 |
| `name_en` | テキスト | 欧文名 | カードで姓名改行。**半角スペース区切り必須** |
| `company` | テキスト | 所属 | |
| `position` | テキスト | 役職 | 空可。TOP では出さず記事だけで使う |
| `profile` | テキストエリア | 略歴 | 記事ヘッダーのみ |
| `site` | URL | 公式サイト | 空可 |
| `portrait` | 画像 | 顔写真 | 一覧カード・記事ヘッダー共用。**アイキャッチと兼ねる** |

`title`（記事タイトル）は WP 標準の投稿タイトルを使う。ACF に持たせない。
`slug` は WP のスラッグ、`image_alt` は画像の代替テキストをそのまま使う。
`logo`（企業ロゴ）は**現在どこにも表示していない**ので移行対象から外す。

> `portrait` をアイキャッチ（`thumbnail`）で兼ねられるなら ACF 項目も1つ減る。
> 運用上「アイキャッチ＝一覧に出る顔写真」と決められるかで判断。

### 4-2. `site_settings`（ACF オプションページ）

全ページ共通の値。いまの `entries.json` の `site` 直下にあたる。

| フィールド名 | 型 | 対応 |
|---|---|---|
| `catch` | テキスト | サイトのリード文 |
| `concept_lines` | リピーター（テキスト1つ） | Hero のコンセプト文。1行＝1レコード |
| `group_colors` | リピーター（カラー1つ・5件） | グループの色 |
| `sbs_url` | URL | 協力（SBSラジオ）のリンク先 |
| `ogp_image` | 画像 | OGP 既定画像 |

Hero のコンセプト文をリピーターにしておくと、**1文字ずつ打つ演出の行割りを
管理画面から変えられる**（いまは HTML 直書き）。

### 4-3. `story_closing`（任意・投稿タイプ `story`）

記事末尾の「応援メッセージ」。本文の最後を2カラム（文＋写真）で組んでいる。
本文の並びから推測している現状の判定をやめ、明示的に持たせる。

| フィールド名 | 型 |
|---|---|
| `closing_text` | テキストエリア |
| `closing_image` | 画像 |

## 5. 本文（content）の設計

要件どおり**本文と写真は WP の本文エディタで管理**する。
ただし現状の表示は Q&A のバッジ・写真の帯・章見出しの罫を**クラスで組んで
いる**ので、素の段落と画像を置くだけでは同じ見た目にならない。

そこで**カスタムブロックを2つ**登録し、エディタが必要なクラス付きの HTML を
そのまま保存する形にする。

### 5-1. 登録するブロック

| ブロック | 用途 | 出力 |
|---|---|---|
| `spotlight/qa` | 質問・回答 | `.p-article__qa--q` / `--a` + バッジ |
| `spotlight/photo-band` | 連続写真の帯 | `.c-marquee`（2枚以上で流れる帯） |

### 5-2. コアブロックで足りるもの

| 内容 | 使うブロック | 出力先クラス |
|---|---|---|
| 章見出し（`h`） | 見出し（H2） | `.p-article__heading` |
| 地の文（`p`） | 段落 | `.p-article__p` |
| 単独写真（`img`） | 画像 | `.p-article__figure`（本文に回り込む） |

コアブロックはクラスが付かないので、**テーマ側で `the_content` に
フィルタを掛けて付与**する（`h2` → `.p-article__heading` など）。
ブロックの `render_callback` でもよい。

### 5-3. 移行スクリプト

`data/articles/*.json` の `body` は種別付きなので、**ブロック HTML へ機械変換
できる**。20件を手で貼り直す必要はない。

```
h   → <!-- wp:heading {"level":2} --><h2>…</h2><!-- /wp:heading -->
p   → <!-- wp:paragraph --><p>…</p><!-- /wp:paragraph -->
q,a → <!-- wp:spotlight/qa {"kind":"q"} -->…<!-- /wp:spotlight/qa -->
img → 連続する数で振り分け
      1枚   : <!-- wp:image -->
      2枚以上: <!-- wp:spotlight/photo-band -->
```

写真は URL のままでは WP のメディアに入らないので、
`media_sideload_image()` で取り込んでから ID を差し替える。
（現在の40枚は `spotlight-miyazaki.com` を直リンクしている）

## 6. テーマ側で必要な処理

いま `assets/js/main.js` がブラウザで組み立てているものを、PHP へ移す。

| いまの処理 | 移行先 |
|---|---|
| `renderVoices()` グループ分け・カード生成 | `front-page.php` のループ |
| `buildBody()` 本文組み立て | ブロック側で完結（5章） |
| 単独写真の左右振り分け | `the_content` フィルタで通し番号を振る |
| 記事の canonical / og:url 差し替え | **PHP で静的に出力**（7章） |

**JS に残すもの**（そのまま流用できる）：

- Hero の演出一式（`initOpeningHero`）
- VOICE のカルーセル（`initVoiceCarousel`）
- パララックス、フェードイン、ハンバーガー

これらは DOM に対して動くだけでデータを持たないので、
出力元が JSON から PHP に変わっても手を入れずに済む。

---

## 7. WP 化で解消すること

いま静的構成のせいで**できていない**ことが、移行すると自然に直る。

| 現状の制限 | WP 化後 |
|---|---|
| 記事ごとの OGP が出せない（クローラが JS を実行しないため、全記事が共通カード） | slug ごとに `<head>` を静的出力できる |
| 記事が `?slug=` のクエリ URL | `/story/{slug}/` のパス URL |
| `entry.html` が `noindex` | 記事ごとに `index` を出せる |
| データ更新に `tools/gen-data.mjs` の実行が必要 | 管理画面で完結 |

## 8. 決めてほしいこと

1. **25件の内訳** — 5組×5件で確定か。いまは4組20件＋COMING SOON 2組。
2. **CONTACT の送信先** — プラグイン（Contact Form 7 / Snow Monkey Forms）か、
   外部フォームか。現状 `<form>` に `action` がなく送信されない。
3. **アイキャッチと顔写真を兼ねるか** — 兼ねられれば ACF が1項目減る。
4. **企業ロゴ（`logo`）** — 現在どこにも出していない。WP でも持たないでよいか。
5. **グループの色** — 5組ぶんの色。4組ぶんは既存の値がある。
6. **`noindex`** — 公開時に記事から外す想定でよいか。
